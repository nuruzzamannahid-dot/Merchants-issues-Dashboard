## 2026-07-25 - [Preventing Hardcoded API Keys and Ensuring Safe Startup Validation Checks]
**Vulnerability:** Hardcoded Telegram bot token and credentials leaked in both source file (`carrybee_reminder_bot.py`) and configuration documentation (`README.md`).
**Learning:** Hardcoding API keys or other sensitive credentials in code repositories poses a high security risk, as they can be easily harvested by malicious actors. Additionally, when implementing startup environment variable validation checks in imported Python modules (such as `carrybee_reminder_bot.py`), the validation and program exit routine must be placed inside the `if __name__ == '__main__':` block. Doing so prevents test runners, linters, and other importing processes from terminating prematurely with non-zero exit codes during automated testing.
**Prevention:** Always load sensitive credentials from environment variables (e.g. using `os.environ.get`) and restrict any process-terminating validation checks (e.g., `sys.exit`) to the entry point block of the module. Ensure any documented API keys or credentials use redacted placeholders like `<REDACTED_TELEGRAM_BOT_TOKEN>`.
